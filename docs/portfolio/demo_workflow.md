# Reproducible sales-cleaning demonstration

Use only [portfolio_sales_raw.csv](../../sample_data/portfolio_sales_raw.csv), a
fictional dataset. Its missing values and inconsistent formats are intentional.
Keep the source file untouched. Slash dates in this dataset mean **day/month/year**.

## Run the existing Streamlit interface

Install and launch from the repository root as described in [README](../../README.md).
Select **Reset workspace** if another dataset or workflow is loaded.

1. In **Upload**, use the file uploader to select `sample_data/portfolio_sales_raw.csv`.
   Leave CSV encoding at **Detect Unicode** and delimiter at **Detect automatically**.
   Select **Load dataset**. This new fixture is uploaded; it is not an added item
   in the application's existing bundled-sample selector.
2. In **Data Overview**, verify **12 rows, 8 columns, 3 missing cells, 2 duplicate rows**.
   Inspect the original table: leading zeros, spaces and inconsistent casing are
   preserved. Order 000102 and order 000107 each occur twice.
3. In **Cleaning Configuration**, add these steps in exactly this order. Expand
   each step to set its parameters. Use Move up/Move down to correct the order.

| Step | Operation | Exact settings |
| --- | --- | --- |
| 1 | Clean text | Columns `customer`, `region`, `status`, `quantity`, `unit_price`; operation `trim`. |
| 2 | Clean text | Columns `customer`, `region`, `status`; operation `lower`. |
| 3 | Remove duplicates | Compare **All columns**; retain **First record**; no case-insensitive columns. |
| 4 | Convert numbers | Columns `quantity`, `unit_price`; decimal `.`; thousands **None**. |
| 5 | Handle missing values | Columns `quantity`, `unit_price`; action `median`. |
| 6 | Handle missing values | Column `region`; action `constant`; type **Text**; value `unknown`. |
| 7 | Standardize dates | Column `order_date`; input formats `%Y-%m-%d` and `%d/%m/%Y`, one per line. |

Duplicate removal precedes median calculation so repeated records do not bias the
fill. Numeric conversion precedes median calculation because CSV values load as
strings. The declared date formats make day/month order explicit.

4. Keep **Stop preview processing on the first step with errors** enabled. Select
   **Preview changes**. There should be no processing errors.
5. In **Results**, enable **Show original and result side by side** and compare the
   tables. Review the summary and step details; no original data is overwritten.
   Verify the results below before checking **I reviewed this preview and want to
   apply these changes.** Select **Apply reviewed changes**.
6. In **Download**, select **Prepare downloads**, then download CSV, XLSX and JSON.
   These exports contain all ten rows. XLSX reports a precision warning: eight
   Decimal cells are stored as text. This is expected preservation behavior, not
   a processing failure. This dataset contains no formulas, so it needs no formula
   acknowledgment. The separate synthetic sparse workbook demonstrates that safeguard.

## Expected result

| --- | ---: | ---: |
| Rows | 12 | 10 |
| Columns | 8 | 8 |
| Missing cells | 3 | 0 |
| Duplicate rows after first occurrence | 2 | 0 |

- Order 000105: region becomes `unknown` by explicit constant fill.
- Order 000106: missing quantity becomes `2`, the median after duplicate removal.
- Order 000108: missing price becomes `14.50`, the median after duplicate removal.
- Order 000110: quantity ` 2 ` becomes numeric `2`; price ` 18.00 ` becomes numeric
  `18`. Values are preserved; original display formatting is not a cleaning contract.
- Dates become `2026-10-01` through `2026-10-10`. Order identifiers keep their zeros.
- Customer/region/status text is lowercase and trimmed; product labels stay intact.

## Reproduce without the UI

After installation, from the repository root:

```powershell
.\.venv\Scripts\python.exe scripts/run_portfolio_demo.py
```

On macOS/Linux, substitute `.venv/bin/python`. The script reads
[demo_steps.json](demo_steps.json), uses the existing public pipeline/export APIs,
and creates these files under ignored `.demo-output/`:

- `portfolio_sales_cleaned.csv`
- `portfolio_sales_cleaned.xlsx`
- `portfolio_sales_report.json` — the engine's processing report
- `demo_summary.json` — original hash, before/after profiles and export diagnostics

Re-running replaces these generated artifacts only; it does not edit the raw data.
An optional `--output-dir PATH` selects another destination. Keep private outputs
out of Git. Do not commit generated XLSX copies when the script can reproduce them.

The dashboard does **not** import pipeline JSON configurations: enter the seven
steps manually for the UI demonstration. Dashboard JSON downloads additionally
include export statuses and acknowledgment; the script keeps export diagnostics in
`demo_summary.json`. Both use the same processing engine and yield the same values.
